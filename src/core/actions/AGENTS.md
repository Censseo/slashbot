## Layer Pattern

Architectural role: Two-phase action system - plugins register XML tag parsers, core routes LLM-generated tags to plugin handlers. The executor dispatches actions and collects results.

File convention: `parser.ts` (registration + parsing), `executor.ts` (dispatch + execution), `types.ts` (shared types)

## Function Signatures & Spec Sources

| Function | Signature | Purpose |
|----------|-----------|---------|
| registerActionParser | `(config: ActionParserConfig) => void` | Register plugin's XML tag parser |
| parseActions | `(content: string) => Action[]` | Extract actions from LLM response |
| executeActions | `(actions: Action[], handlers: ActionHandlers) => Promise<ActionResult[]>` | Execute all parsed actions |
| clearActionParsers | `() => void` | Reset parser registry (testing) |
| extractAttr | `(tag: string, attr: string) => string \| null` | Extract XML attribute value |
| extractBoolAttr | `(tag: string, attr: string) => boolean` | Extract boolean XML attribute |
| setDynamicExecutorMap | `(map: Map<string, Function>) => void` | Set plugin executor dispatch map |

## Expected Errors

| Error | Handling | Context |
|-------|----------|---------|
| Unknown action type | Skip with warning | Parser returns type not in executor map |
| Handler missing | Return null result | Plugin didn't register handler |
| Execution failure | Catch, return error ActionResult | Handler threw exception |

## Guard Rails

| Rule | Reason |
|------|--------|
| DO NOT bypass parser registration | All action tags must go through registerActionParser |
| DO NOT modify Action type without updating all parsers | Breaking change across 20+ plugins |
| Transparent actions (say, continue) execute before real actions | UX requirement for immediate feedback |
