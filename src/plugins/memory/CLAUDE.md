## Code Patterns

### Plugin Tool Registration

Tools are registered inline in `setup()` via `context.registerTool()`. No separate `tools.ts` file — plugin follows the new SDK pattern (not the legacy `getToolContributions()` pattern).

```typescript
context.registerTool({
  id: 'memory.search',
  title: 'Search',
  pluginId: PLUGIN_ID,
  description: '...',
  parameters: z.object({ query: z.string(), limit: z.number().optional() }),
  execute: async (args) => {
    try {
      // ...
      return { ok: true, output: result as unknown as JsonValue };
    } catch (err) {
      return { ok: false, error: { code: 'MEMORY_SEARCH_ERROR', message: String(err) } };
    }
  },
});
```

### Service Registration

Services are registered via `context.registerService()` — not InversifyJS `container.bind()`. This is the new plugin SDK pattern.

```typescript
context.registerService({
  id: 'memory.store',
  pluginId: PLUGIN_ID,
  description: 'Markdown-based memory store',
  implementation: store,
});
```

### Event Subscription for Auto-Extraction

On every `memory:upserted` event, the plugin fires-and-forgets graph extraction. The LLM call is non-blocking; extraction errors are swallowed.

```typescript
eventBus.subscribe('memory:upserted', (event) => {
  const text = event.payload?.text;
  if (text && typeof text === 'string') {
    graph.extractAndMerge(text, llmAdapter).catch(() => {});
  }
});
```

### Graph Search Expansion

When `expand: true` (default), `memory.search` passes the graph instance to `store.search()`. The store uses graph neighbors to run secondary BM25 passes; expanded hits are returned at 50% score with `source: 'graph'`.

## Error Handling

**Pattern**: All tool `execute()` handlers are wrapped in try/catch and return typed error objects.

```typescript
// Success
return { ok: true, output: value as unknown as JsonValue };

// Failure
return { ok: false, error: { code: 'MEMORY_SEARCH_ERROR', message: String(err) } };
```

Error codes follow the convention `{DOMAIN}_{VERB}_ERROR`:
- `MEMORY_SEARCH_ERROR`, `MEMORY_GET_ERROR`, `MEMORY_UPSERT_ERROR`, `MEMORY_STATS_ERROR`, `MEMORY_NOTE_ERROR`
- `GRAPH_RELATED_ERROR`, `GRAPH_ASSOCIATE_ERROR`, `GRAPH_PATH_ERROR`

Graph-internal errors (extraction, flush) are swallowed silently to avoid disrupting the user-facing write path.

## Business Invariants

| ID | Invariant | Enforcement |
|----|-----------|-------------|
| — | Graph MUST NOT exceed 5,000 nodes without warning | `addNode()` warns at 5,000 via `console.warn` |
| — | File paths passed to `memory.get` MUST NOT escape `.slashbot/` directory | `resolve()` + `relative()` path check throws on `..` prefix |
| — | Edge weight is bounded `[0.5, 1.0]`; initial weight 0.5, reinforced by +0.1 per duplicate | `addEdge()` clamps at `Math.min(1.0, weight + 0.1)` |
| — | Graph flush permissions MUST be 0o600 | `fs.writeFile(..., { mode: 0o600 })` |
| — | LLM extraction errors MUST NOT surface to the user | `extractAndMerge()` wraps in try/catch, errors swallowed |

## State Machines & Lifecycle

### AssociationGraph Lifecycle

```
constructor(workspaceRoot)
    → load()          [async, called by plugin setup, non-blocking via .catch()]
    → addNode/addEdge [marks dirty, schedules 500ms flush timer]
    → flush()         [coalesces writes, resets dirty flag]
    → cancelFlush()   [cleanup on shutdown]
```

**Key states**:
- `dirty = false` — graph matches persisted JSONL
- `dirty = true, flushTimer set` — pending write (debounced 500ms)
- Flush rewrites entire JSONL from in-memory Maps (no delta append)

## Guard Rails

| Rule | Reason |
|------|--------|
| DO NOT call `extractAndMerge` with `noTools: false` or `maxSteps > 1` | Extraction must be a single, cheap LLM call; multi-step would loop |
| DO NOT surface graph flush errors to the user | Flush is background I/O; errors must be logged only |
| DO NOT store absolute paths in JSONL | Graph uses workspace-relative paths only |
| DO NOT import AssociationGraph directly into other plugins | Resolve via `context.getService('memory.graph')` to avoid tight coupling |
| DO NOT add nodes with empty/whitespace labels | `slugify('')` produces empty ID which collides |
| DO NOT use `BASE_RELATIONS` as an allowlist; custom relations are valid | List is advisory/canonical, not an enforced enum |

## Gotchas

- **Flush timer leaks in tests**: Always call `graph.cancelFlush()` in `afterEach` or use `vi.useFakeTimers()` when testing graph mutations. The 500ms timer keeps the process alive.
- **LLM extraction session ID is static**: `extractAndMerge` uses `sessionId: 'graph-extraction'` — do not rely on session isolation for extraction calls.
- **JSONL rewrite semantics**: Every `flush()` rewrites the full file, not just appending deltas. On large graphs this may be slow; the 5,000-node warning is the guard.
- **`source: 'graph'` hits may have duplicate content**: Graph expansion runs independent BM25 passes that can surface the same memory file at different line numbers. The deduplication key is `path:line`.
