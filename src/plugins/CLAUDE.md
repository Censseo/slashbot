## Code Patterns

### Canonical Plugin Structure

**When to use**: Every new plugin MUST follow this structure.

```
src/plugins/<plugin-name>/
  index.ts       # Plugin class (REQUIRED)
  types.ts       # Action type interfaces
  parser.ts      # XML action tag parser configs
  executors.ts   # Action execution handlers
  tools.ts       # AI SDK tool definitions (Zod schemas)
  prompt.ts      # Prompt contribution strings
  commands.ts    # Slash command handlers (optional)
  services/      # Business logic services (optional)
```

**File reference**: `src/plugins/bash/` (canonical example)

### Plugin Class Template

**When to use**: Starting a new plugin.

```typescript
import type { Plugin, PluginMetadata, PluginContext, ActionContribution, PromptContribution } from '../types';
import { registerActionParser } from '../../core/actions/parser';

export class MyPlugin implements Plugin {
  readonly metadata: PluginMetadata = {
    id: 'core.my-plugin',
    name: 'MyPlugin',
    version: '1.0.0',
    category: 'core',
    description: 'Description',
  };

  private context!: PluginContext;

  async init(context: PluginContext): Promise<void> {
    this.context = context;
    // Register action parsers
    for (const config of getMyParserConfigs()) {
      registerActionParser(config);
    }
    // Self-register services in DI (optional)
    // context.container.bind(TYPES.MyService).toConstantValue(service);
  }

  getActionContributions(): ActionContribution[] {
    const context = this.context;
    const onMyAction = async (param: string) => { /* handler */ };
    return [{ type: 'my-action', tagName: 'my-action', handler: { onMyAction }, execute: executeMyAction }];
  }

  getPromptContributions(): PromptContribution[] {
    return [{ id: 'core.my-plugin.tools', title: 'My Tools', priority: 50, content: MY_PROMPT }];
  }
}
```

### Tool Contribution (AI SDK)

**When to use**: Preferred over XML tags for new plugins.

```typescript
import { z } from 'zod/v4';
import type { ToolContribution } from '../types';

export function getBashToolContributions(): ToolContribution[] {
  return [{
    name: 'bash',
    description: 'Execute a shell command',
    parameters: z.object({
      command: z.string().describe('The command to execute'),
      timeout: z.number().optional().describe('Timeout in ms'),
    }),
    toAction: (args) => ({ type: 'bash', command: args.command as string }),
    controlFlow: 'continue',
  }];
}
```

## Component Structure

### Plugin Lifecycle

1. `loadBuiltinPlugins()` - Instantiate all 24 plugins
2. `PluginRegistry.registerAll()` - Store plugins
3. Topological sort by `metadata.dependencies`
4. `initAll()` - Call `plugin.init(context)` in dependency order
5. `onBeforeGrokInit()` - Pre-API hooks (optional)
6. Collect contributions (actions, prompts, commands, tools, context, events, sidebar)
7. `onAfterGrokInit()` - Post-API hooks (optional)
8. Runtime operation
9. `destroyAll()` - Teardown in reverse order

## Error Handling

**Pattern**: Handler returns `{ success, message/error }`, executor formats for display

```typescript
// In action handler (plugin)
const onBash = async (command: string) => {
  try {
    const result = await executeCommand(command);
    return { success: true, message: result };
  } catch (error: any) {
    return { success: false, error: error?.message || String(error) };
  }
};

// In executor
export async function executeBash(action, handlers): Promise<ActionResult | null> {
  if (!handlers.onBash) return null;
  display.tool('Bash', action.command);
  const result = await handlers.onBash(action.command);
  return { action: `Bash: ${action.command}`, success: result.success, result: result.message || '', error: result.error };
}
```

## Guard Rails

| Rule | Reason | Source |
|------|--------|--------|
| DO NOT put feature logic outside plugins | Violates plugin-first principle | constitution.md |
| DO NOT import between plugins directly | Use EventBus or DI for cross-plugin communication | architecture-registry |
| DO NOT skip dependency declaration | Causes init order failures | PluginRegistry sort |
| DO NOT use `getGrokClient()` before `onAfterGrokInit()` | Client not available yet | Plugin lifecycle |
| DO NOT block in `init()` (long operations) | Violates 2s combined init budget | constitution.md |
| DO NOT add new plugins without adding to loader.ts | Plugin won't be loaded | Plugin loading |
