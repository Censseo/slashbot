## Code Patterns

### Connector Implementation

**When to use**: Adding a new platform connector.

```typescript
export class MyConnector implements Connector {
  readonly source: ConnectorSource = 'my-platform';
  readonly config = PLATFORM_CONFIGS['my-platform'] || PLATFORM_CONFIGS.cli;

  private messageHandler!: MessageHandler;
  private eventBus?: EventBus;
  private replyTargetId: string;

  setMessageHandler(handler: MessageHandler): void { this.messageHandler = handler; }
  setEventBus(eventBus: EventBus): void { this.eventBus = eventBus; }

  async start(): Promise<void> {
    const lock = await acquireLock('my-platform');
    if (!lock.acquired) { /* graceful exit */ return; }
    // Connect to platform...
    this.eventBus?.emit({ type: 'connector:connected', source: this.source });
  }

  async sendMessage(text: string): Promise<void> {
    const chunks = splitMessage(text, this.config.maxMessageLength);
    for (const chunk of chunks) { await this.sendToApi(chunk); }
  }
}
```

**File reference**: `src/connectors/telegram/connector.ts`

### Reply Target Tracking

**When to use**: All connectors must track where to send replies.

```typescript
// On message receive:
this.replyTargetChatId = ctx.chat.id.toString();

// sendMessage uses tracked target:
async sendMessage(text: string): Promise<void> {
  return this.sendMessageTo(this.replyTargetChatId, text);
}
```

### Continuous Typing Indicator

**When to use**: Show typing during LLM processing.

```typescript
await ctx.telegram.sendChatAction(chatId, 'typing');
const typingInterval = setInterval(() => {
  ctx.telegram.sendChatAction(chatId, 'typing').catch(() => {});
}, 4000); // Telegram typing expires after ~5s
// ... process message ...
clearInterval(typingInterval);
```

### Session-Scoped Context

**When to use**: Each channel/chat gets isolated conversation.

```typescript
await this.messageHandler(message, 'telegram', {
  sessionId: `telegram:${chatId}`,
  chatId,
});
```

### Lock-Based Singleton

**When to use**: Prevent multiple instances of same connector.

```typescript
const lock = await acquireLock('telegram');
if (!lock.acquired) {
  display.connector('telegram', `Locked by PID ${lock.existingPid}`);
  return; // Exit gracefully
}
// ... connect ...
// Lock auto-released on process exit
```

## Error Handling

**Pattern**: Graceful degradation, never crash

```typescript
// Connection error: release lock, emit disconnected
try {
  await bot.launch();
} catch (error) {
  releaseLock('telegram');
  this.eventBus?.emit({ type: 'connector:disconnected', source: 'telegram' });
  throw error;
}

// Message send error: truncate for platform limits
try {
  await ctx.reply(text, { parse_mode: 'MarkdownV2' });
} catch {
  await ctx.reply(text); // Fallback: plain text (no markdown)
}

// Telegram error truncation: max 500 chars to avoid "message too long"
const errorMsg = error.message?.substring(0, 500) || 'Unknown error';
```

## State Machines & Lifecycle

### Connector Lifecycle

**States**: unconfigured -> configured -> locked -> connected -> running

```text
unconfigured -> configured: Bot token + channel/chat ID provided
configured -> locked: acquireLock() succeeds
locked -> connected: Platform SDK connected
connected -> running: Message handler set, ready for messages
running -> disconnected: stop() called or error
disconnected -> configured: Lock released, ready to restart
```

**Invalid Transitions**:

| From | To | Reason |
|------|----|--------|
| unconfigured | locked | Cannot lock without config |
| locked -> running (skip connected) | - | Must connect to platform first |

## Guard Rails

| Rule | Reason | Source |
|------|--------|--------|
| DO NOT broadcast to all connectors | Use `notify(message, target)` with explicit target | ConnectorRegistry design |
| DO NOT remove primary chatId/channelId | Protected in addChat/removeChat methods | Connector auth model |
| DO NOT skip lock acquisition | Prevents duplicate bot instances | ADR-005 |
| DO NOT store bot tokens in config.json | Tokens are secrets, go to credentials.json | Security invariant |
| DO NOT ignore typing indicators | User expects feedback during LLM processing | UX requirement |
