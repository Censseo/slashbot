## Overview

Slashbot's security model spans command safety (dangerous shell pattern blocking), file operation guards (max deletion ratios), git operation allowlists, a per-command permission system, and wallet encryption (AES-256-GCM with password-derived keys). Security is enforced both at parse time (blocking dangerous patterns before execution) and at the service level (encrypted storage, session-based auth).

## Security Layers

| Layer | Mechanism | Scope |
|-------|-----------|-------|
| Shell safety | Dangerous pattern blocking at parse time | `rm /`, fork bombs, privilege escalation |
| File safety | Max deletion ratio (80%), path validation | Prevents accidental file wipes |
| Git safety | Allowlist of safe commands | No force-push, no destructive resets |
| Wallet encryption | AES-256-GCM, PBKDF2-like key derivation | Private keys, seed phrases |
| Session auth | Request-body signing with keypair | Proxy API authentication |
| Permissions | Per-command allow/deny stored in permissions.json | Configurable per-project |
