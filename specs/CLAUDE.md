## Cross-Cutting Concerns

> Patterns that span multiple features and modules.
> Follow these consistently when specifying or implementing any feature.

### Authentication & Authorization

**Pattern**: Multi-layer auth depending on context
**File reference**: `src/plugins/wallet/provider.ts`, `src/plugins/system/services/CommandPermissions.ts`
**Applies to**: Wallet proxy auth (request-body signing), connector auth (chatId/channelId whitelists), command permissions (permissions.json)

### Error Response Format

**Standard format**:

```typescript
interface ActionResult {
  action: string;      // Description of action performed
  success: boolean;    // Whether action succeeded
  result: string;      // Result message/data
  error?: string;      // Error message if failed
}
```

**File reference**: `src/core/actions/types.ts`
**Convention**: All plugin executors return ActionResult; display.errorText() for user-facing errors

### Validation Patterns

**Pattern**: Input validation at system boundaries using blocklists and allowlists
**File reference**: `src/core/config/constants.ts` (DANGEROUS_PATTERNS), `src/plugins/git/` (allowlist)
**Convention**: Validate shell commands against blocklist; validate file paths against working directory; validate connector messages against authorized IDs

### Logging & Observability

**Pattern**: Display-based output via centralized DisplayService singleton
**File reference**: `src/core/ui/display.ts`
**Convention**: `display.tool()` for action indicators, `display.errorText()` for errors, `display.successText()` for success. TUI mode redirects stdout to ChatPanel via OutputInterceptor. No structured logging framework (gap).
