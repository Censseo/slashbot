# Implementation Plan: Admin Dashboard

**Branch**: `010-admin-dashboard` | **Date**: 2026-03-09 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/010-admin-dashboard/spec.md`

## Summary

Add an admin dashboard view to the existing web UI SPA. The dashboard displays plugin status, live streaming logs, and system health metrics. Implementation is primarily frontend work (Alpine.js + Tailwind CSS) leveraging existing backend endpoints (GET /api/plugins, GET /api/logs, RPC webui.systemInfo), with one new backend endpoint for status indicators.

## Technical Context

**Language/Version**: TypeScript (strict mode) on Bun 1.0+ (backend), JavaScript ES2022+ (frontend)
**Primary Dependencies**: Alpine.js 3.x (CDN), Tailwind CSS (CDN), PenguinUI components
**Storage**: N/A (stateless dashboard — all data fetched from existing APIs)
**Testing**: Vitest (backend handler tests)
**Target Platform**: Desktop browser (≥1024px primary), self-hosted Linux server
**Project Type**: Web application (backend plugin + frontend static files)
**Performance Goals**: LCP < 2s, log render < 100ms, health refresh < 500ms
**Constraints**: No build step for frontend, CDN-only dependencies, single SPA page
**Scale/Scope**: Single operator, ~25 plugins, log stream variable throughput

## Architecture Alignment Report

| Capability | Pattern | Alignment | Notes |
|------------|---------|-----------|-------|
| Status indicators endpoint | HTTP route registration | ALIGNED | Same pattern as /api/plugins |
| Dashboard frontend | Alpine.js x-data component | ALIGNED | Same pattern as chat.js |
| Log streaming client | EventSource (GET SSE) | NEW PATTERN | Chat uses fetch (POST); logs use GET → EventSource is appropriate |
| Tab navigation | Client-side SPA routing | NEW PATTERN | First multi-view navigation in the SPA |
| Auth token reuse | Bearer token in localStorage | ALIGNED | Same `slashbot_token` key |

**New patterns**: EventSource for GET-based SSE, tab-based SPA navigation. Both are standard web patterns, justified by the specific requirements (GET endpoint, state preservation).
